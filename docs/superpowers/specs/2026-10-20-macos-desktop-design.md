# SnapBerry macOS 데스크톱 추가

사용자는 기존 SnapBerry를 맥북에서 사용하고 다른 앱의 화면을 직접 캡처하려고 한다. iPhone 앱이 아닌 macOS 앱이며 Apple Silicon과 Intel을 모두 대상으로 한다. 기존 Windows 편집기는 유지한다.

## 이번 구현의 범위

독립 실행 가능한 Avalonia 데스크톱 앱을 추가한다. 영역·창·주 모니터 캡처, 이미지 열기, 화살표·텍스트·사각형·모자이크·번호 주석, 선택·이동·크기 조절·삭제, Undo/Redo, 이미지 추가, 자르기, PNG 저장, 이름·날짜 검색이 있는 로컬 이력, 화이트·다크 테마를 제공한다. 기존 Windows 리본·전역 단축키·전체 스티커 카탈로그의 완전한 이식은 다음 단계다. 앱 안의 단축키는 Command 기준으로 제공한다.

## 구조와 결정

- `SnapBerry.Core`의 문서·배치·히트 테스트·실행 취소를 재사용한다.
- `SnapBerry.Desktop`은 `net10.0`, Avalonia 12.1.4, SkiaSharp로 구성한다. Windows WPF 프로젝트를 참조하지 않는다.
- 기존 `.qcapture` 저장소 파일은 Desktop 프로젝트에서 소스 링크하여 같은 저장 형식을 유지한다. 저장소의 WPF 크기 검사 의존성만 Core의 동일한 검사로 교체한다. 기존 공개 이름과 JSON 스키마는 유지한다.
- `DesktopEditor`는 PNG·문서·주석·자원과 명령 이력을 관리한다. `SkiaDocumentRenderer`는 미리보기와 PNG 출력에 같은 합성 경로를 사용한다. `EditorSurface`는 포인터를 문서 좌표로 변환하고 드래그 미리보기만 표시한다.
- 첫 캡처 구현은 macOS 기본 `/usr/sbin/screencapture`를 `ProcessStartInfo.ArgumentList`로 호출한다. 사용자 명령에서만 실행하고 영역·창 선택은 OS UI에 맡긴다. 직접 ScreenCaptureKit 브리지를 요구하지 않아 Windows에서도 관리 앱과 두 아키텍처를 빌드할 수 있다. 이후 네이티브 캡처 서비스로 교체할 수 있는 인터페이스를 둔다.
- 캡처 전 창을 숨기고 성공·취소·실패 모두 창 상태를 복원한다. ESC 취소는 기존 문서·이력을 변경하지 않는다. 임시 캡처 파일은 성공·실패 모두 제거한다. 권한 오류는 사용자에게 표시한다.
- 맥 데이터는 `~/Library/Application Support/SnapBerry`에 저장한다. Windows 시험용 데이터와 분리한다. 저장 실패 시 기존 문서를 유지하고 닫기·전환을 중단한다.
- 양쪽 CPU용 자체 포함 `.app` 번들을 생성한다. Windows에서 생성한 번들은 실행 비트·서명이 검증되지 않았으므로 미검증 산출물로 명시하고 macOS의 최종 패키징 스크립트를 제공한다. 외부 서버나 자동 업데이트는 추가하지 않는다.

## 검증과 한계

실제 창·앱 활성화·클립보드·화면 캡처는 실행하지 않는다. 캡처 프로세스를 대체한 테스트, Core 및 Desktop 문서·렌더링·저장 실패 테스트, Avalonia 헤드리스 레이아웃을 실행한다. 일반 Windows Release 빌드와 Portable 게시·번들 검증을 유지한다. macOS 실기기의 권한·OS 선택 UI·서명·Retina 배율·두 CPU에서의 실행은 맥에서 추가 확인해야 한다.

성공 기준은 맥용 앱 코드와 두 아키텍처 번들이 빌드되고, 캡처 결과 또는 가져온 이미지를 주석 편집·저장·재열기할 수 있는 경로가 자동 테스트로 검증되는 것이다. 맥에서 실행해 확인했다는 주장은 하지 않는다.
