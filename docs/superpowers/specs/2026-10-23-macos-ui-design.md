# macOS 편집 UI 정리

## 목적과 범위

macOS용 `SnapBerry.Desktop`의 기존 편집 기능을 유지하면서 회색 텍스트 버튼이 여러 줄로 늘어서는 화면을 정리한다. Windows 배포 앱인 `SnapBerry.App` 및 공통 편집 모델은 변경하지 않는다. Avalonia의 Windows 실행에서도 Desktop 프로젝트의 새 UI는 보이지만 Windows용 WPF 제품에는 적용되지 않는다.

## 접근 방식

- **선택한 방식:** Avalonia를 유지하고 도구 모음·이력 사이드바·편집 캔버스로 재배치한다. 기존 명령 연결과 렌더러, 캡처·저장·이력 동작을 재사용한다. 사용자가 이 방향을 선택했다.
- 기존 배치의 색상·간격만 수정하는 방식은 상단의 과밀함을 충분히 해결하지 못한다.
- AppKit 전체 재작성은 편집기와 OS 기능의 연결을 다시 검증해야 하므로 이번 범위에 넣지 않는다.

## 화면 설계

1. 네이티브 제목 표시줄과 macOS 창 버튼을 유지한다. 가짜 macOS 창 테두리나 신호등 버튼을 그리지 않는다.
2. 상단 도구 모음에는 사이드바 토글, 이미지 열기·붙여넣기, 영역·창·전체 화면 캡처, 복사·PNG 저장을 배치한다. 설정·단축키·정보는 보조 명령 영역에 둔다. 관련 명령은 작은 그룹으로 구분하며 아이콘과 짧은 이름을 사용한다.
3. 왼쪽에는 이력 제목, 검색, 썸네일 목록, 이름 편집 및 기존 이력 작업을 둔다. 사이드바 너비와 접기 상태 저장을 유지한다.
4. 편집 영역 상단에는 선택·화살표·텍스트·사각형·모자이크·번호·스티커·자르기를 배치한다. 실행 취소·다시 실행·선택 개체 작업을 구분한다. 도구 모음이 좁으면 스크롤할 수 있게 하여 명령이 잘리지 않도록 한다.
5. 도구별 속성은 기존처럼 필요한 항목만 표시한다. 긴 항목도 작은 창에서 접근할 수 있도록 스크롤 및 줄바꿈을 제공한다.
6. 중앙은 중립색 캔버스로 두고, 빈 화면에는 아이콘·짧은 안내·영역 캡처 버튼을 정돈해 배치한다. 하단에는 상태·이미지 크기·확대 비율을 유지한다.

## 시각 기준

시스템 글꼴을 사용하고 제목·본문·보조 설명의 위계를 구분한다. 라이트 모드에서는 밝은 회색 사이드바와 흰 도구 모음, 다크 모드에서는 대응하는 중립색을 사용한다. 보라색은 주요 동작·선택·포커스에 제한한다. 버튼은 둥근 모서리와 얇은 경계를 사용하며, 모든 아이콘 명령에 읽을 수 있는 이름과 툴팁을 제공한다. SF Symbols나 외부 글꼴 설치에 의존하지 않는다.

## 대화상자

정보 창은 앱 아이콘·이름·버전·만든이·링크를 한 덩어리로 정돈하고, 상세 정보와 법적 문서는 기존 확장 영역으로 유지한다. 불필요한 고정 높이를 줄인다. 설정 및 단축키 창은 설명·입력 그룹·하단 취소/저장으로 구성하고 주요 저장 버튼을 강조한다. 다른 편집 대화상자도 공통 색상·간격·컨트롤 스타일을 따르게 한다.

## 유지할 동작

이미지 열기·붙여넣기·추가, 3종 캡처, 모든 주석 도구와 속성, 스티커, 자르기, 실행 취소·다시 실행, 복제·삭제·내용 편집, PNG 저장, 복사, 이미지 크기 조절, 줌·팬, 이력 검색·이름 변경·복제·다중 삭제·페이지 추가, 테마·로그인 실행·전역 단축키, 메뉴 막대 및 트레이, 정보·법적 문서·외부 링크를 유지한다. 문서가 없거나 작업 중인 경우의 비활성화도 유지한다.

## 검증

- Desktop 헤드리스 테스트로 도구·명령 연결, 선택 상태, 모달·작업 중 비활성화, 좁은 창 접근성, 라이트·다크 렌더링을 확인한다.
- 렌더링은 메모리에서 수행하며 실제 앱 실행·화면 캡처·포커스 이동은 하지 않는다. 렌더링 결과를 이미지로 검토한다.
- 관련 테스트 및 공통 Core 테스트, 일반 Release 빌드, Windows Portable 프로필의 로컬 게시를 수행한다. Windows 제품 소스는 수정하지 않고 기존 사용자 변경도 보존한다.
- 현재 환경은 Windows이므로 실제 macOS 창 장식·메뉴·글꼴·Retina 렌더링은 이번 로컬 검사로 확정하지 않는다.
- 커밋·푸시·GitHub 배포는 이번 요청에 포함하지 않는다.
