# Windows 개인 업무용 화면 캡처 앱 설계서

개인 업무에서 화면을 빠르게 캡처하고 주석을 넣어 공유하는 Windows 전용 데스크톱 앱을 개발한다. 첫 버전은 캡처, 주석 편집, 클립보드 복사, PNG 저장, 캡처 이력 보관과 재편집까지 하나의 흐름으로 제공한다.

문서 상태: 캡처 이력 요구를 반영한 구현 전 검토안. 작성일: 2026년 10월 14일. 캡처 이력 보관·재편집·삭제를 첫 버전 범위에 포함한다. 아래 세부 저장 방식은 구현을 위한 설계안이다.

# 목표와 범위

핵심 사용 흐름은 단축키 실행 → 캡처 → 주석 편집 → 복사 또는 저장이다. 설치 후 관리자 권한 없이 실행하고, 화면 내용은 로컬에서 처리한다.

| 첫 버전에 포함 | 이후 버전으로 보류 |
| --- | --- |
| 영역, 창, 전체 화면 캡처 | 스크롤 캡처, 동영상 녹화 |
| 화살표, 텍스트, 번호, 스티커, 사각형, 모자이크 | OCR, 자동 번역, 클라우드 공유 |
| 주석 선택, 이동, 삭제, 크기 조정 | 편집 프로젝트 가져오기·내보내기 |
| 실행 취소, 다시 실행 | 플러그인, 자동 업데이트 |
| 클립보드 복사, PNG 저장 | 복잡한 이미지 보정과 자유형 그리기 |
| 트레이 상주, 전역 단축키 설정 | macOS와 Linux 지원 |
| 캡처 이력 자동 보관, 다시 열어 편집, 선택 삭제 | 이력 검색·태그·클라우드 동기화 |

지원 목표는 Windows 10 22H2 및 Windows 11의 x64 환경이다. 실제 배포 전 대상 OS에서 동작을 검증한다. 첫 버전은 스크린샷 한 장을 하나의 편집 문서로 다루며, 여러 문서의 탭 편집은 제공하지 않는다.

# 캡처와 편집 흐름

## 실행과 트레이

최초 실행 시 작은 캡처 패널을 표시한다. 패널에는 캡처 모드와 캡처 버튼이 있고, 닫으면 트레이에 남는다. 트레이 메뉴에서 캡처, 편집창 열기, 캡처 이력, 설정, 종료를 제공한다. 중복 실행하면 기존 인스턴스를 활성화한다. Windows 시작 시 자동 실행은 기본적으로 꺼져 있으며 설정에서 선택한다.

초기 단축키는 영역 Ctrl+Shift+1, 창 Ctrl+Shift+2, 전체 화면 Ctrl+Shift+3으로 제안한다. 등록에 실패한 단축키는 사용 불가 상태와 원인을 표시하며, 설정에서 다른 조합으로 바꾼다. 기존에 정상 등록된 단축키는 새 조합 등록에 성공한 뒤 교체한다.

## 영역 캡처

앱의 캡처 패널과 편집창을 잠시 숨긴 뒤 바탕 화면을 캡처하고, 정지된 화면 위에서 영역을 선택한다. 드래그한 사각형의 실제 픽셀 크기를 표시한다. 마우스를 놓으면 선택 영역으로 편집창을 연다. Esc는 캡처를 취소하고 이전 앱 상태를 복원한다. 폭이나 높이가 0인 선택은 캡처하지 않는다.

## 창 캡처

포인터 아래의 캡처 가능한 최상위 창을 강조하고 클릭으로 선택한다. 창 경계는 보이는 프레임을 기준으로 계산하며 앱 자체 창은 제외한다. 첫 버전은 바탕 화면에서 보이는 창 영역을 잘라 캡처하므로, 다른 창에 가려진 내용은 복원하지 않는다. 최소화된 창과 보안 데스크톱은 지원하지 않는다.

## 전체 화면 캡처

전체 화면은 가상 데스크톱에 연결된 모든 모니터를 한 이미지로 캡처하는 동작으로 정의한다. 모니터 사이의 빈 공간은 불투명 검정으로 채운다. 현재 모니터만 캡처하는 모드는 이후 확장 항목이다.

## 편집 중 새 캡처

새 캡처, 이전 이력 열기, 앱 종료 전에 입력 중인 텍스트를 확정하고 현재 편집 상태의 이력 저장을 완료한다. 자동 저장이 성공하면 PNG 출력 여부와 관계없이 문서를 전환할 수 있다. 저장 실패 시 현재 문서를 유지하고 재시도 또는 전환·종료 취소를 제공한다. 트레이로 숨기는 동작은 문서를 유지하고 자동 저장을 계속한다. PNG 내보내기 대화상자의 취소는 내부 이력과 편집 내용을 변경하지 않는다.

# 편집 화면과 도구

편집 화면은 상단 도구막대, 접을 수 있는 왼쪽 캡처 이력 목록, 중앙 이미지 캔버스, 하단 상태 표시줄로 구성한다. 원본 이미지는 기본적으로 창에 맞춰 표시하며 줌과 스크롤을 제공한다. 줌은 편집 표시 배율만 바꾸고 내보내기 해상도는 바꾸지 않는다.

도구막대에는 선택, 화살표, 텍스트, 번호, 스티커, 사각형, 모자이크, 실행 취소, 다시 실행, 복사, 저장을 배치한다. 아이콘에 툴팁과 접근성 이름을 제공하고, 선택한 도구의 색상·선 두께·글자 크기 등 필요한 속성만 표시한다. 조작 상태에 따라 사용할 수 없는 명령은 비활성화한다.

| 도구 | 동작 |
| --- | --- |
| 선택 | 위에 있는 주석부터 선택하고, 드래그 이동·핸들 크기 조정·Delete 삭제 |
| 화살표 | 시작점과 끝점을 드래그로 지정하고 색상과 두께 변경 |
| 텍스트 | 위치 클릭 후 입력, 다시 선택해 내용과 색상·크기 수정 |
| 사각형 | 드래그 생성, 테두리 색상과 두께 변경, 기본 채움 없음 |
| 모자이크 | 영역을 지정하고 블록 크기를 원본 픽셀 단위로 변경 |
| 번호 | 클릭마다 숫자 또는 영문 소문자 순번을 삽입하고, 선택 후 표시값·색상·크기 수정 |
| 스티커 | 분류별 목록에서 골라 클릭 삽입, 위치 이동·비율 유지 크기 조정·삭제 |

## 스티커 도구

스티커 도구를 선택하면 분류 탭과 미리보기 격자를 표시한다. 항목에는 이름과 툴팁을 제공하며 선택 후 캔버스를 클릭하면 삽입한다. 선택한 스티커를 유지해 연속 삽입할 수 있고, 배치 전 Esc는 취소한다. 스티커는 독립 주석으로 선택·이동·비율 유지 크기 조정·삭제할 수 있으며 실행 취소와 자동 저장에 포함한다.

첫 버전은 다음 48개 기본 항목을 제공한다. 실제 아이콘은 자체 제작하거나 배포·재배포가 허용되는 자산을 사용하며 출처와 라이선스를 배포물에 포함한다.

| 분류 | 기본 항목 |
| --- | --- |
| 이모지 12개 | 미소, 웃음, 슬픔, 화남, 놀람, 하트, 별, 엄지 위, 엄지 아래, 박수, 전구, 축하 |
| 키보드 키 14개 | Ctrl, Shift, Alt, Win, Enter, Esc, Tab, Space, Backspace, Delete, 상·하·좌·우 화살표 |
| 체크와 엑스 6개 | 단독 체크, 원형 체크, 사각형 체크, 단독 엑스, 원형 엑스, 사각형 엑스 |
| 기호 8개 | 주의, 정보, 물음표, 정지, 원, 사각형, 삼각형, 마름모 |
| 방향 화살표 8개 | 상·하·좌·우와 네 대각선 방향 |

키보드 키는 키캡 형태의 이미지로 제공하고, 표시 문자열을 바꿔 F1 또는 Ctrl+C 등 업무에 필요한 키와 조합을 만들 수 있다. 빈 문자열은 허용하지 않으며 긴 문자열에 맞춰 키캡 폭을 늘린다. 변경된 키캡은 해당 주석에만 적용한다. 일반 스티커의 종횡비는 고정하며 키캡 문자열 변경은 고유 비율을 다시 계산한다.

이모지는 운영체제 글꼴에 의존하지 않는 투명 컬러 PNG를 사용해 편집 화면과 저장 이미지에서 동일하게 보이도록 한다. 기호와 키캡은 고해상도 투명 PNG로 제공하며, 키캡 문자열을 변경하면 같은 스타일로 다시 렌더링한다. 첫 버전은 사용자 스티커 파일 가져오기와 온라인 스티커 다운로드를 포함하지 않는다.

기본 삽입 크기는 긴 변 64 원본 픽셀이다. 원본 비율로 크기를 조절하고 출력 시에는 선택 테두리 없이 합성한다. 자산 픽셀 크기를 넘는 확대는 가능하지만 화질은 원본 해상도의 영향을 받는다.

캡처 이력에는 사용한 스티커 PNG와 주석 위치·크기·표시 문자열을 함께 저장한다. 같은 PNG는 SHA-256으로 식별해 캡처 파일 안에서 한 번만 보관한다. 키캡 표시 문자열을 수정하면 새 PNG와 해시를 생성한다. 다시 열기, 삭제·실행 취소·재실행, PNG 출력과 클립보드 복사에서 같은 모습을 유지한다. 손상되거나 누락된 자산은 오류로 알려 원본 저장 파일을 덮어쓰지 않는다.

## 번호 도구

번호 도구를 선택한 뒤 이미지에서 클릭하면 원형 배지 안에 순번을 넣는다. 숫자 모드는 1, 2, 3으로, 영문 소문자 모드는 a, b, c로 증가한다. 영문은 z 다음 aa, ab로 이어진다. 모드는 세그먼트 선택으로 전환하며 다음에 삽입할 값은 숫자 입력 또는 영문 입력에서 수정할 수 있다.

새 캡처는 숫자 1, 영문 a에서 시작한다. 두 모드의 다음 값을 문서별로 독립 관리하므로 숫자 1, 2를 넣고 영문 a, b를 넣은 후 숫자로 돌아오면 3을 삽입한다. 클릭 삽입 성공 때만 해당 모드의 값을 증가시킨다. 다음 값 입력은 양의 정수 또는 영문 소문자만 허용하고 잘못된 입력은 기존 값을 유지한다.

삽입한 배지는 선택·이동·크기 조정·삭제가 가능하고 더블클릭 또는 속성 입력으로 표시값을 직접 수정할 수 있다. 표시값 수정은 다른 배지와 다음 자동 순번에 영향을 주지 않는다. 빈 표시값은 허용하지 않는다. 배경색·글자색·배지 크기를 변경하며 긴 표시값은 배지 안에 맞춰 글자를 줄여 표시한다.

배지 삽입과 순번 증가는 하나의 실행 취소 항목이다. 삽입을 실행 취소하면 다음 순번도 복원하고 다시 실행하면 같은 배지와 순번을 복원한다. 기존 배지를 삭제해도 나머지를 다시 번호 매기지 않는다. 모드·다음 값 변경과 배지 편집도 실행 취소 및 자동 저장에 포함한다.

캡처 이력에는 배지의 표시값·위치·스타일과 선택 모드·두 가지 다음 값을 함께 저장한다. 다시 열었을 때 기존 배지를 수정하고 이어지는 순번을 삽입할 수 있다.

첫 버전은 단일 주석 선택만 지원한다. 생성 순서를 겹침 순서로 사용하고 별도 레이어 패널은 제공하지 않는다. 텍스트는 한글 IME 조합을 지원하며 입력 중 단축키가 편집 명령과 충돌하지 않도록 한다.

텍스트 입력 확정 전에는 복사·저장·도구 전환이 현재 입력을 먼저 확정한다. Esc는 진행 중인 도형 생성·이동을 취소하고 텍스트 입력에서는 수정 전 내용으로 돌아간다. 빈 텍스트 주석은 제거한다.

Ctrl+Z와 Ctrl+Y는 실행 취소·다시 실행, Ctrl+S는 저장이다. 텍스트 입력에 포커스가 있으면 일반 복사 키는 텍스트 복사로 동작하고, 전체 이미지 복사는 도구막대의 명령으로 구분한다.

# 기술 구성

C#과 WPF를 사용하고 MVVM으로 화면 상태와 편집 로직을 분리한다. 구현 시점에 공식 지원 중인 .NET LTS 버전을 선택해 고정한다. Windows 기능은 작은 서비스 인터페이스 뒤에 두어 좌표 변환과 주석 동작을 독립적으로 검증한다.

| 구성 요소 | 책임 |
| --- | --- |
| AppHost | 단일 인스턴스, 트레이, 앱 수명 관리 |
| HotkeyService | 전역 단축키 등록, 해제, 충돌 보고 |
| CaptureService | 가상 데스크톱 스냅샷과 창 경계 조회 |
| CaptureOverlay | 모니터별 선택 오버레이와 캡처 좌표 계산 |
| EditorViewModel | 현재 도구, 선택, 줌, 변경 상태 관리 |
| AnnotationDocument | 원본 이미지와 주석 목록 보관 |
| CommandHistory | 편집 명령의 실행 취소와 다시 실행 |
| CompositeRenderer | 원본과 주석을 출력용 이미지로 합성 |
| ExportService | 클립보드 복사와 PNG 파일 저장 |
| SettingsService | 단축키, 마지막 저장 폴더, 도구 속성 저장 |
| CaptureLibraryStore | 원본·주석·메타데이터의 영속 저장, 다시 열기와 삭제 |
| CaptureLibraryViewModel | 썸네일 목록, 선택, 다시 열기와 삭제 명령 |
| AutosaveCoordinator | 편집 저장 예약, 전환 전 저장 완료와 실패 복구 |

첫 캡처 구현은 Win32의 화면 DC와 비트맵 복사를 사용하는 방식으로 잡는다. 창 선택은 포인터 위치와 최상위 창 정보로 처리하고, 프레임 경계 조회를 사용한다. 캡처 서비스가 대체 가능하도록 분리하되 Windows Graphics Capture 등 다른 백엔드 구현은 첫 버전에 포함하지 않는다.

네이티브 핸들과 이미지 버퍼는 명시적으로 해제한다. 클립보드 접근은 UI의 STA 스레드에서 처리하고, 큰 이미지의 합성과 파일 인코딩은 UI 입력을 막지 않도록 실행한다. UI에 전달하는 이미지 객체는 스레드 경계를 고려해 고정하거나 복사한다.

# 좌표와 화면 배율

원본 이미지와 주석의 기준 좌표는 캡처 이미지의 실제 픽셀이다. WPF 화면의 DIP 좌표와 편집 줌은 표시 단계에서만 적용한다. 앱은 Per Monitor V2 DPI 인식을 사용하도록 구성한다.

가상 데스크톱에는 음수 좌표의 모니터가 존재할 수 있다. 선택 결과는 가상 데스크톱 기준의 물리 픽셀 사각형으로 만든 뒤, 스냅샷 원점만큼 이동해 이미지 좌표로 변환한다. 모니터마다 별도 오버레이를 두고 하나의 선택 상태를 공유해 혼합 배율에서도 드래그 영역을 연결한다.

이미지 경계를 벗어난 주석 부분은 출력에서 잘라낸다. 선 두께와 글자 크기는 원본 픽셀 기준이므로 줌을 바꿔도 저장 결과가 달라지지 않는다. 모니터 연결이나 배율이 캡처 선택 도중 바뀌면 선택을 취소하고 다시 캡처하도록 안내한다.

# 문서와 실행 취소 모델

원본 이미지는 편집 중 변경하지 않는다. AnnotationDocument는 이미지 폭·높이, 원본 픽셀, 생성 순서가 있는 주석 목록을 가진다. 각 주석에는 고유 ID, 종류, 위치·크기 또는 양 끝점, 종류별 스타일이 저장된다. 텍스트는 내용과 글꼴 크기를, 모자이크는 블록 크기를 추가로 보관한다. 번호 주석은 표시 문자열을 별도로 보관하며, 문서에는 번호 모드와 숫자·영문 각각의 다음 순번을 저장한다. 스티커 주석은 내장 스티커 ID, 표시 크기와 키보드 키의 표시 문자열을 저장한다. 사용한 스티커의 투명 PNG 자산을 내부 캡처 파일에 포함해 앱 버전이 바뀌어도 같은 모습으로 다시 편집한다.

추가·삭제·내용 수정·스타일 수정·이동·크기 조정을 명령으로 기록한다. 한 번의 드래그는 마우스 이동 횟수와 관계없이 한 개의 실행 취소 항목이다. 실행 취소 뒤 새 편집을 하면 다시 실행 목록을 비운다. 새 캡처는 새로운 문서와 이력으로 시작한다. 이전 캡처를 다시 열면 저장된 원본과 마지막으로 저장된 주석 상태를 복원하고 실행 취소·다시 실행 스택은 비운다. 앱 재시작을 넘는 실행 취소 이력은 저장하지 않는다.

모자이크는 원본 이미지의 해당 영역을 기준으로 계산하고 일반 주석보다 먼저 합성한다. 겹친 모자이크 영역은 더 큰 블록 크기를 우선 적용하며, 그 위에 화살표·사각형·텍스트·번호·스티커를 생성 순서대로 그린다. 편집 화면과 출력은 같은 합성 규칙을 공유한다. 민감 정보에는 충분한 블록 크기를 사용해야 하며, 첫 버전의 모자이크는 완전한 정보 제거를 보장하는 가림 도구로 정의하지 않는다.

주석 선택 테두리와 조절 핸들은 편집 화면에만 표시하며 출력에 포함하지 않는다. 파일로 저장된 PNG에는 합성된 픽셀만 들어가며 원본 이미지·편집 이력·주석 객체를 함께 넣지 않는다.

# 캡처 이력 보관과 재편집

## 자동 보관

완료된 캡처는 PNG 내보내기나 클립보드 복사 여부와 관계없이 앱 내부 이력에 자동 저장한다. 캡처를 취소한 경우 항목을 만들지 않는다. 첫 저장이 실패하면 새 캡처를 메모리의 편집창에서 유지하고 미저장 상태와 재시도를 제공하며, 기존 이력을 보존한다.

주석의 추가·이동·삭제·내용·스타일 변경과 실행 취소·다시 실행 결과를 저장한다. 확정된 편집 후 500ms 지연으로 자동 저장하며 진행 중 드래그와 한글 IME 조합은 확정 전 저장하지 않는다. 다른 캡처 열기·새 캡처·종료 전에 편집을 확정하고 저장 완료를 기다린다. PNG 출력 상태와 내부 이력 저장 상태는 별도로 관리한다.

## 이력 목록

편집창 왼쪽의 접을 수 있는 목록에 썸네일, 캡처 시각, 픽셀 크기를 최신 캡처부터 표시한다. 목록은 페이지 단위로 읽고 썸네일을 지연 로딩한다. 선택 항목을 더블클릭하거나 열기 명령으로 다시 편집한다. 첫 실행의 캡처 패널과 트레이에서도 이력 화면을 열 수 있다. 앱 재시작 후 이력을 표시하며 현재 문서를 자동으로 여는 대신 선택해서 열도록 한다.

원본 이미지와 마지막 저장된 주석의 위치·내용·스타일·겹침 순서와 번호 도구의 다음 순번를 복원한다. 재편집은 같은 이력 항목을 갱신하고 새 캡처 항목을 추가하지 않는다. 캡처 목록은 여러 항목을 보관하지만 동시에 편집하는 문서는 한 개다.

## 저장 구조와 복구

LocalAppData/QuickCapture/Library에 항목별 GUID 이름의 .qcapture 파일을 둔다. 각 파일은 ZIP 컨테이너로 원본 original.png와 schemaVersion=1인 document.json을 함께 저장한다. JSON은 ID, UTC 캡처·수정 시각, 이미지 크기, 캡처 모드, 생성 순서의 주석 목록을 포함한다. 화면 시각은 사용자 로컬 시간으로 표시한다. 스티커를 사용한 항목에는 document.json에서 참조한 assets/<sha256>.png도 포함한다. 주석은 자산 해시와 스티커 ID를 보관한다.

저장 시 같은 폴더의 임시 파일에 원본과 주석을 완성한 후 기존 항목을 교체한다. 실패 시 마지막 정상 항목을 유지하며 초기 생성 중 불완전한 파일은 목록에 노출하지 않는다. 항목별 저장을 직렬화하고 최신 상태를 순서대로 저장한다. 앱 시작 시 미완료 임시 파일은 정식 이력으로 취급하지 않는다.

미리보기는 주석을 합성한 이미지에서 생성해 ID별 캐시로 보관한다. 캐시가 없거나 오래되면 재생성하며, 삭제한 항목의 캐시는 제거한다. 목록은 정식 파일의 메타데이터에서 재구성하므로 별도 목록 인덱스가 손상되어도 이력을 잃지 않는다. 지원하지 않는 스키마나 손상 항목은 오류 상태로 표시하며 자동 덮어쓰기·삭제하지 않는다.

## 삭제와 보관 정책

선택한 이력 한 개 또는 여러 개를 삭제할 수 있다. 선택 개수와 복원 불가를 안내한 뒤 확인하면 앱 저장소의 원본·주석과 미리보기 캐시를 삭제한다. 삭제 작업 자체는 주석 실행 취소로 되돌리지 않는다. 삭제 실패 항목은 목록에 남기고 실제 성공한 항목만 제거한다.

현재 편집 중인 항목을 삭제하면 해당 항목의 자동 저장을 차단하고 진행 중 저장이 끝난 뒤 삭제하여 항목이 다시 생성되지 않게 한다. 성공하면 편집창을 비운다. 취소나 실패 시 문서를 유지하고 필요한 저장을 재개한다. 외부에 내보낸 PNG와 이미 복사한 클립보드 내용은 삭제하지 않는다.

사용자가 삭제할 때까지 보관하며 개수·날짜 기준의 자동 삭제는 제공하지 않는다. 디스크가 부족하면 저장 실패를 알려 기존 항목을 유지하고 삭제 후 재시도하도록 한다. 내부 이력에는 모자이크 적용 전 원본도 보관한다. 삭제는 앱 파일 제거이며 저장 장치의 복구 불가능한 완전 삭제를 보장하지 않는다.

# 저장과 오류 처리

PNG 저장은 원본 캡처 해상도를 유지한다. 기본 파일명은 Capture_yyyyMMdd_HHmmss.png이며 마지막 저장 폴더를 기억한다. 기존 파일을 덮어쓸 때 확인하고, 같은 폴더에 임시 파일로 인코딩한 후 교체하여 저장 실패 시 기존 파일을 최대한 보존한다. 실패한 저장을 성공으로 표시하지 않는다.

클립보드에는 합성 이미지의 비트맵을 제공한다. 클립보드가 잠겨 있으면 제한된 횟수로 재시도하고, 계속 실패하면 오류와 재시도 명령을 표시한다. 복사·저장 성공 시 상태 표시줄에 결과를 알려준다.

캡처 실패, 파일 쓰기 실패, 메모리 부족 시 기존 편집 문서를 유지한다. 예상 캡처 크기와 작업 버퍼를 확인하고 처리할 수 없는 크기는 캡처 전에 알려준다. 보호된 콘텐츠는 검게 나오거나 캡처되지 않을 수 있으며 이를 복구하는 기능은 제공하지 않는다.

설정 파일은 사용자 LocalAppData의 앱 전용 폴더에 JSON으로 보관하고 버전 필드를 둔다. 손상된 설정은 백업 후 기본값으로 복구한다. 화면 이미지, 텍스트 주석, 클립보드 내용은 진단 로그에 기록하지 않는다. 자동 업로드와 원격 분석 수집은 제공하지 않는다.

자동 검증은 픽셀 좌표 변환, 명령 이력, 모자이크 겹침과 합성 순서 등 오류 위험이 높은 로직에 집중한다. 캡처, 전역 단축키, IME, 클립보드, DPI 이동은 실제 Windows 환경의 통합 검증으로 확인한다.

일반적인 1920×1080 캡처에서 선택 확정 후 편집 가능 상태까지 1초 이내를 성능 목표로 둔다. 결과에는 측정 장비와 조건을 함께 기록한다. 4K 캡처 50회를 반복하면서 메모리와 GDI 핸들이 지속 증가하지 않는지 확인한다. 이 수치는 구현 전 목표이며 검증 결과가 아니다.

# 구현 순서와 배포

1. 앱 수명, 트레이, 단축키, 화면 스냅샷과 영역 캡처를 연결한다.

2. 창·전체 화면 캡처를 추가하고 혼합 DPI와 음수 좌표를 검증한다.

3. 원본 이미지와 주석 모델, 편집 캔버스, 도구와 명령 이력을 구현한다.

4. 합성 렌더러, 클립보드, PNG 저장과 설정을 연결한다.

5. 오류·취소·변경 확인을 보완하고 실제 Windows 환경에서 완료 기준을 검증한다.

첫 개발 배포는 .NET 런타임을 포함한 x64 폴더 배포 ZIP으로 제공한다. 사용자는 압축 해제 후 실행한다. 설치 프로그램, 코드 서명, 자동 업데이트는 이후 배포 단계에서 결정한다. 캡처 이력은 실행 파일 폴더와 분리된 사용자 LocalAppData에 보관하므로 앱 배포 폴더를 교체해도 유지한다. 외부 PNG는 합성 이미지이고 재편집은 앱 내부 이력의 원본과 주석을 이용한다.

# Snagit 참고와 설계 근거

Snagit은 캡처 후 주석을 넣는 사용 흐름의 참고 제품이다. 이 설계는 승인된 기능 범위에 대한 독립적인 구현안이며 Snagit 내부 코드나 파일 형식을 재현하는 요구사항은 없다.

현재 Snagit 실행 파일이나 런타임에서 얻은 REA 분석 증거는 없다. 향후 설치 파일이 제공되면 캡처 선택, 주석 조작, 저장 흐름 중 필요한 항목만 분석하고 관찰된 동작과 자체 설계 결정을 구분한다. 아이콘, 이미지, 소스 코드 등 제품 자산은 자체 제작하거나 적절한 라이선스의 자산을 사용한다.
