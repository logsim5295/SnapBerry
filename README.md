# SnapBerry

Windows 개인 업무용 화면 캡처 및 주석 편집 앱입니다. C#/.NET 10과 WPF로 구현했습니다.

**Windows 다운로드:** [최신 릴리스의 ZIP](https://github.com/logsim5295/SnapBerry/releases/latest) · [최신 EXE](https://github.com/logsim5295/SnapBerry/releases/latest/download/SnapBerry.exe)

**macOS 다운로드:** [Apple Silicon DMG](https://github.com/logsim5295/SnapBerry/releases/latest/download/SnapBerry-macos-arm64.dmg) · [Intel DMG](https://github.com/logsim5295/SnapBerry/releases/latest/download/SnapBerry-macos-x64.dmg)

macOS용 Avalonia 시험 버전도 별도 프로젝트로 추가했습니다. 영역·창·전체 화면 캡처, 주석 편집·이력·PNG 저장과 Command+C/V 클립보드, 한국어 스티커, 설정 가능한 전역 캡처 단축키와 메뉴 막대 상주를 제공합니다. Apple Silicon·Intel 모두 GitHub의 맥 환경에서 실제 설치·실행·최초 화면 기록 권한 승인·캡처·클립보드·전역 단축키를 검사합니다. 설치·빌드·지원 기능은 [macOS 안내](docs/macos.md)를 참고하세요.

위 Release 다운로드는 GitHub 로그인 없이 이용할 수 있습니다. 맥 설치는 CPU별 DMG를 열어 SnapBerry를 응용 프로그램 폴더로 옮긴 뒤 실행합니다. 터미널이나 별도 .NET 설치는 필요하지 않습니다. 현재 Developer ID 서명·공증 전 시험 버전이므로 첫 실행 시 보안 승인이 필요할 수 있습니다. [설치 안내](docs/macos.md#터미널-없이-설치하기)를 참고하세요.

GitHub Actions의 `macOS verification`은 두 CPU에서 빌드·헤드리스 테스트·패키지와 네이티브 라이브러리 로딩·DMG 서명을 검사하고 결과와 설치 파일을 보관합니다. 실행 방법과 검증 범위는 [맥 자동 검증 안내](docs/macos.md#github-actions-자동-검증)에 있습니다.

## 무료 배포와 데이터 처리

Windows용 SnapBerry는 무료 소프트웨어입니다. 개인·기업·기관에서 업무 및 영리 활동을 포함해 무료로 사용할 수 있으며, 원본 EXE의 무료 공유를 허용합니다. 프로그램 수정·유료 재판매 등은 별도 허락이 필요합니다. 자세한 조건은 [이용약관](LICENSE.txt), 저장·삭제·외부 전송에 관한 설명은 [데이터 처리 안내](DATA-PROCESSING.md)를 확인하세요. 외부 구성 요소에는 각 구성 요소의 라이선스가 적용됩니다.

GitHub 공개 저장소는 GitHub 서비스 약관이 허용하는 범위에서 열람·포크할 수 있습니다. 소스 코드 공개가 오픈소스 라이선스 부여를 의미하지 않으며, 해당 허용 범위를 넘는 수정·파생 프로그램 제작·수정본 배포와 프로그램의 유료 재판매 등에는 제작자의 사전 허락이 필요합니다. 법령과 외부 구성 요소의 라이선스가 부여하는 권리는 유지됩니다.

앱의 **정보 → 이용약관 및 데이터 처리 안내**에서 약관·데이터 처리·외부 구성 요소 문서를 인터넷 없이 읽고 복사할 수 있습니다. 원문은 EXE에 내장되며 배포 폴더에도 함께 제공됩니다. EXE를 공유할 때는 내장 고지를 유지하고, 문서 파일도 함께 제공하는 것을 권장합니다.

캡처 이력에는 모자이크·자르기 전 원본 이미지가 보관됩니다. 외부 공유에는 내부 `.qcapture` 파일 대신 이미지 내보내기를 사용하고 결과물을 확인하세요. 로그에는 실행 경로나 예외 정보가 들어갈 수 있으므로 문의에 첨부하기 전에 확인하세요.

## Windows 설치

Windows x64용 포터블 앱입니다. 설치 프로그램, 별도 .NET 설치 또는 관리자 권한이 필요하지 않습니다.

1. [최신 릴리스](https://github.com/logsim5295/SnapBerry/releases/latest)에서 Windows 배포 ZIP(`SnapBerry-v<버전>-win-x64.zip`)을 다운로드합니다.
2. ZIP 전체를 원하는 폴더에 압축 해제합니다. `SnapBerry.exe`, `LICENSE.txt`, `DATA-PROCESSING.md`, `THIRD-PARTY-NOTICES.md`가 함께 들어 있습니다.
3. 이용약관과 데이터 처리 안내를 확인한 뒤 `SnapBerry.exe`를 실행합니다. 약관·안내는 앱의 **정보 → 이용약관 및 데이터 처리 안내**에서도 읽을 수 있습니다.

[최신 EXE](https://github.com/logsim5295/SnapBerry/releases/latest/download/SnapBerry.exe)만 다운로드해서 실행할 수도 있습니다. 파일 무결성을 확인하려면 릴리스에 첨부된 `SHA256SUMS.txt`와 다운로드한 파일의 SHA-256을 비교하세요.

## Windows 업데이트

자동 업데이트 기능은 없으며 새 배포본으로 직접 교체합니다.

1. [최신 릴리스](https://github.com/logsim5295/SnapBerry/releases/latest)에서 새 ZIP을 다운로드하고 별도 폴더에 압축 해제합니다.
2. 실행 중인 SnapBerry의 트레이 메뉴에서 **종료**를 선택합니다. 창의 닫기 버튼은 트레이에 남기므로 EXE 교체 전에 완전히 종료해야 합니다.
3. 중요한 이력이 있다면 `%LOCALAPPDATA%\SnapBerry` 폴더를 별도 위치에 복사해 백업합니다.
4. 기존 실행 폴더의 `SnapBerry.exe`와 안내 문서를 새 파일로 교체한 뒤 실행합니다. 앱의 **정보**에서 버전을 확인할 수 있습니다.

이력과 설정은 EXE 옆이 아닌 `%LOCALAPPDATA%\SnapBerry`에 저장되므로 EXE 교체 시 유지됩니다. 업데이트를 위해 이 데이터 폴더를 삭제할 필요가 없습니다. Windows 자동 실행을 사용 중이면 기존 EXE 위치를 유지하세요. 실행 폴더를 옮겼다면 새 위치에서 앱을 실행하고 설정의 **Windows 시작 시 실행**을 껐다가 다시 켜세요.

## 실행과 기본 설정

창을 닫으면 트레이에 남습니다. 트레이 메뉴의 종료는 저장 중인 캡처 이력을 완료한 뒤 앱을 종료합니다.

설정의 ‘화면 테마’에서 화이트 모드·다크 모드를 선택합니다. 설정창에서 미리 본 뒤 저장하면 편집기·대화상자·트레이 메뉴에 바로 적용되고 다음 실행에도 유지됩니다. 기본값은 화이트 모드이며 테마 변경은 이미지·주석 색상에 영향을 주지 않습니다.

## 캡처와 편집

- 배경 지우개: Windows 홈 리본과 macOS 편집 도구 모음에서 **배경 지우개**를 선택한 뒤 원본 이미지의 색상을 클릭합니다. 보라색 선택 미리보기를 확인하고 **색상 범위**를 조절합니다. 기본은 클릭 지점에 연결된 영역이며, **비슷한 색 모두 선택**을 켜면 현재 자르기 영역 전체의 같은 색을 선택합니다. **선택 지우기** 또는 Delete로 선택 픽셀을 투명하게 만들고 Esc나 다른 도구로 선택을 취소합니다. 선택·색상 범위 조절은 문서를 변경하지 않고, 지우기를 확정하면 실행 취소/다시 실행·자동 저장·복사·내보내기에 반영됩니다. 원본과 도형·텍스트·삽입 이미지는 보존하며, 투명 영역은 체크무늬로 표시합니다. AI 모델·인터넷·토큰 요금이 필요하지 않습니다. 투명 PNG로 저장할 수 있고, 결과 PNG의 자원 한도는 16MiB입니다.
- 기존 이미지 열기: 홈 리본의 이미지 열기 또는 Ctrl+O. PNG·JPEG·BMP·GIF·TIFF 파일을 새 편집 문서로 열며, GIF·TIFF는 첫 프레임을 사용합니다. 사용자 원본 파일은 수정하지 않습니다.
- 클립보드 이미지 붙여넣기: 홈 리본의 이미지 붙여넣기 또는 Ctrl+V. 편집 중인 이미지 위에 이동·크기 조절·삭제가 가능한 이미지 개체로 추가하고, 이미지가 없으면 새 문서로 엽니다. 붙인 이미지는 비율을 유지해 중앙에 배치하며 캔버스보다 크면 축소합니다. 텍스트 입력란에서는 기존 텍스트 붙여넣기를 유지하고, 클립보드에 이미지가 없으면 현재 문서는 유지됩니다.
- 영역 캡처: Ctrl+Shift+1. 드래그로 범위를 지정하고 Esc로 취소합니다.
- 창 캡처: Ctrl+Shift+2. 현재 보이는 창 영역을 선택합니다. 가려진 내용은 복구하지 않습니다.
- 전체 화면: Ctrl+Shift+3. 연결된 모든 모니터를 하나의 이미지로 캡처합니다.
- 단축키는 설정에서 변경합니다. 등록 충돌 시 기존 조합을 유지하고 원인을 표시합니다.
- 화살표, 텍스트, 사각형, 모자이크, 번호와 스티커를 삽입하고 선택·이동·크기 조정·삭제합니다.
- 상단 리본의 홈 탭은 그리기·편집·내보내기 그룹, 보기 탭은 확대·축소와 이력 표시를 제공합니다.
- 이미지 영역에서 마우스 가운데 버튼(휠)을 누른 채 드래그하면 스크롤 가능한 범위 안에서 화면을 팬 이동합니다. 버튼을 놓거나 Esc를 누르면 종료하며 확대율·선택 객체·편집 내용은 유지됩니다.
- 화살표와 사각형은 시작점 클릭 후 끝점 클릭으로 만들거나 드래그할 수 있습니다. 첫 클릭 후 Esc 또는 다른 도구 선택으로 취소합니다.
- 텍스트, 번호 표시값, 키보드 스티커는 더블클릭하거나 편집 버튼으로 수정합니다.
- 번호는 문서별 숫자·영문 소문자·대문자 순번을 따로 유지합니다. z 다음은 aa, Z 다음은 AA입니다. 다음 값도 지정할 수 있으며 번호 값을 편집하면 해당 형식의 다음 순번도 이어집니다.
- 화살표·사각형의 선 모양은 미리보기가 있는 콤보박스에서 실선·파선·점선·일점쇄선·이점쇄선으로 선택합니다. 새 도형의 기본값과 선택한 도형에 적용할 수 있으며 실행 취소·이력 저장·내보내기에도 반영됩니다.
- 스티커는 이모지 24, 키보드 키 26, 체크·엑스 6, 기호 8, 방향 8, 업무 표시 8개로 총 80종입니다.
- 선택 도구에서는 편집할 객체가 있을 때만 색상과 두께를 활성화합니다. 화살표·사각형은 색상과 두께, 텍스트·번호는 색상만 변경할 수 있습니다.
- 자르기 도구에서 이미지의 네 꼭지점을 드래그하면 남길 영역을 미리 보여주고, 마우스를 놓으면 적용합니다. 드래그 중 Esc로 취소하고 실행 취소·다시 실행으로 복구할 수 있습니다. 자른 영역은 이력·복사·이미지 내보내기에 동일하게 적용됩니다.
- Ctrl+Z/Ctrl+Y로 실행 취소·다시 실행, Ctrl+C로 합성 이미지 복사, Ctrl+S로 **이미지 파일 저장**을 실행합니다. 캔버스에서 붙여넣은 이미지 객체를 선택하면 Ctrl+C는 해당 이미지만 복사하고, Ctrl+V로 현재 크기를 유지한 복제본을 중앙에 추가합니다. 이력 목록에서 Ctrl+C를 누르면 선택한 항목 하나를 주석까지 포함해 복사하며, 다른 이미지를 연 뒤 Ctrl+V로 그 위에 붙일 수 있습니다. 텍스트 입력 중에는 TextBox의 키 조작을 유지합니다.
- Windows의 **이미지 파일 저장** 창에서 PNG, JPEG (`.jpg`·`.jpeg`), WebP, BMP, TIFF (`.tif`·`.tiff`), GIF를 선택할 수 있습니다. 처음에는 PNG를 선택하며, 저장에 성공하면 마지막 파일 형식을 기억해 다음 저장과 앱 재실행 후에도 같은 형식과 확장자를 기본으로 제안합니다. 저장을 취소하거나 실패하면 기존 형식을 유지합니다. WebP는 무손실, JPEG는 품질 92로 저장합니다. JPEG·BMP·GIF의 투명 영역은 흰색으로 처리하며, GIF는 256색 정지 이미지로 저장합니다. PNG·TIFF·WebP는 투명도를 유지합니다. 파일명을 직접 입력하면 최종 확장자에 맞는 형식으로 저장하고 해당 형식을 기억합니다. 내부 이력과 클립보드 이미지는 기존 PNG 형식을 유지합니다.
- 두께와 모자이크 블록 크기 슬라이더는 한 번의 드래그를 한 번에 실행 취소합니다. 일반 텍스트는 8192자까지 저장할 수 있으며, 한도를 넘으면 편집창에서 안내하고 적용을 막습니다.

### 창 내부 요소 캡처 (Windows)

창 캡처에서 메시지 박스, 버튼, 입력칸, 패널 위에 마우스를 올리면 감지된 내부 요소에 테두리가 표시됩니다. 클릭하면 표시된 영역을 캡처합니다. 마우스 휠을 위로 돌리면 부모 패널 또는 전체 창으로 범위가 넓어지고, 아래로 돌리면 다시 하위 요소를 선택합니다. Esc로 취소합니다.

앱이 내부 요소 정보를 제공하지 않거나 조회에 실패하면 감지 가능한 자식 창 또는 전체 창을 선택합니다. 이런 경우에는 영역 캡처로 필요한 부분을 직접 지정할 수 있습니다. macOS의 창 캡처 동작은 기존과 같습니다.

## 캡처 이력

이력은 `%LOCALAPPDATA%/SnapBerry/Library`에 `.qcapture` 파일로 자동 보관합니다. 원본 이미지, 주석, 번호 순번과 사용한 스티커 PNG가 함께 들어갑니다. 왼쪽 목록의 항목을 한 번 클릭하면 편집 문서가 열립니다. Ctrl/Shift 클릭은 여러 항목 선택에 사용하며 문서를 전환하지 않습니다.

편집 후 500ms 지연으로 저장합니다. 다른 캡처로 전환하거나 종료할 때는 저장 완료를 기다립니다. 저장에 실패해도 현재 이미지를 클립보드나 다른 위치의 이미지 파일로 내보낼 수 있습니다.

이력 항목의 우클릭 메뉴에서 이름 변경을 선택하거나, 항목 하나를 선택한 뒤 F2를 눌러 이름을 붙이고 바꿀 수 있습니다. 이름은 한 줄 100자까지이며, 비우면 날짜 표시로 돌아갑니다. 같은 이름도 사용할 수 있습니다. 이름 변경은 편집 내용과 실행 취소·다시 실행 이력을 유지합니다.

이미지로 저장할 때는 현재 이력 이름을 기본 파일명으로 제안합니다. 이름이 없으면 기존 날짜·시간 파일명을 사용하고, 파일명에 사용할 수 없는 문자는 `_`로 바꿉니다. 이력 이름 자체는 유지하며 저장 대화상자에서 파일명을 직접 바꿀 수도 있습니다.

이력 목록 위의 이름 검색창은 전체 이력에서 이름 일부를 검색하며 영문 대소문자를 구분하지 않습니다. 검색창을 비우거나 옆의 × 버튼을 누르면 전체 목록으로 돌아갑니다. 검색 결과가 없어도 현재 편집 문서는 유지하며, 새 캡처·이미지 가져오기·복제본을 열면 검색을 해제해 새 항목을 표시합니다.

이력 삭제는 앱의 원본·주석 파일을 제거하며, 내보낸 이미지 파일과 클립보드는 유지합니다. 복원 기능은 없습니다. 모자이크나 자르기를 사용해도 내부 이력에는 원본이 보관됩니다. 외부에 공유할 때는 `.qcapture` 이력 파일 대신 이미지로 내보냅니다. 실행 취소 스택은 앱 재시작 후 복원하지 않습니다.

## 개발

편집기 하단 상태 표시줄의 `가로 × 세로 px` 버튼은 현재 이미지의 출력 크기를 표시합니다. 클릭하면 가로·세로 픽셀 크기를 입력할 수 있으며 비율 유지는 기본으로 켜져 있습니다. 적용하면 이미지와 주석이 함께 확대·축소되고, 실행 취소/다시 실행·자동 저장·이미지 내보내기에 반영됩니다. 원본 이미지와 주석 좌표는 보존됩니다. 자르기 후에는 자른 영역의 출력 크기가 표시되며 이미지가 없거나 작업 중이면 버튼이 비활성화됩니다.

### 단일 EXE 배포

```powershell
dotnet publish src/SnapBerry.App/SnapBerry.App.csproj -c Release -p:PublishProfile=Portable
```

로컬 게시 결과는 `dist/portable-win-x64/SnapBerry.exe`에 생성됩니다. 사용자에게 제공하는 배포본은 [GitHub Releases](https://github.com/logsim5295/SnapBerry/releases/latest)에서 받습니다. Windows x64용이며 DLL과 .NET 실행 환경을 포함합니다. 실행 시 네이티브 구성 요소는 `%TEMP%/.net`에 자동 추출되므로 임시 폴더 쓰기 권한이 필요합니다. 별도 설치나 관리자 권한은 필요하지 않습니다.

Portable 게시 과정에서 저장소 로컬 도구인 Obfuscar 2.2.50을 자동 복원하고, 앱과 Core DLL의 비공개 이름 변경 및 문자열 숨김을 적용한 뒤 단일 EXE로 묶습니다. 난독화 실패 시 게시도 실패합니다. 최초 게시에는 NuGet 접근이 필요합니다. 일반 Release DLL은 수정하지 않습니다.

WPF/BAML 연결과 네이티브 진입점은 `build/obfuscar.xml`의 제외 규칙으로 보존하며, 공개 API 이름은 JSON 저장 형식과 바인딩 호환성을 위해 유지합니다. 이는 기본 난독화이며 디컴파일을 완전히 막거나 모든 공개 이름을 숨기는 보호는 아닙니다. 이름 매핑은 `src/SnapBerry.App/obj/Release/net10.0-windows/win-x64/portable-obfuscation/output/Mapping.txt`에 남으며 배포하지 않습니다. 디버그 심볼도 EXE에 포함하지 않습니다.

실제 EXE 내부의 난독화, 공개 API, JSON 저장 호환성과 Core 실행을 창 없이 확인할 수 있습니다.

```powershell
dotnet run --project tools/PortableVerification -- .
```

배포 파일은 GitHub Releases로만 제공합니다. Git에는 소스·빌드 스크립트·문서를 보관하며 EXE·DMG·생성된 설치 ZIP은 커밋하거나 Git LFS로 추적하지 않습니다. 새로 복제한 작업 사본에는 실행 파일이 없으므로, 사용자는 Releases에서 다운로드하고 개발자는 위 명령으로 로컬 빌드합니다. 현재 소스와 빌드에는 Git LFS 설치가 필요하지 않습니다.

프로그램 수정 시 관련 테스트와 일반 Release 빌드, 위 Portable 게시로 검증하고 소스 변경만 커밋합니다. 정식 배포는 버전 태그를 푸시해 Release Actions에서 생성합니다. 기존 커밋·태그의 LFS 이력은 유지하며, 이번 정책 변경은 새 커밋부터 적용합니다.

일반 개발용 Release 빌드 설정은 변경하지 않습니다. 캡처 이력과 설정은 EXE 옆이 아닌 사용자별 `%LOCALAPPDATA%/SnapBerry`에 저장됩니다. 설정 파일은 `settings.json`, 진단 로그는 `Logs` 폴더에 저장합니다. 프로그램을 업데이트할 때는 트레이에서 완전히 종료한 뒤 EXE를 교체합니다.

### 일반 빌드

```powershell
dotnet restore SnapBerry.sln --locked-mode
dotnet build SnapBerry.sln -c Release
dotnet test SnapBerry.sln -c Release
dotnet publish src/SnapBerry.App/SnapBerry.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o artifacts/SnapBerry-win-x64
```

## 버전 태그 자동 릴리스

[Release Actions](https://github.com/logsim5295/SnapBerry/actions/workflows/release.yml)는 `v1.2.3` 형식의 새 버전 태그를 푸시하면 Windows x64 EXE·ZIP과 Apple Silicon·Intel macOS DMG를 빌드해 공개 릴리스에 첨부합니다. 안내 문서와 `SHA256SUMS.txt`도 함께 올리며, 다운로드에는 GitHub 로그인이 필요하지 않습니다.

```powershell
git tag -a v1.2.3 -m 'SnapBerry 1.2.3 공개 배포'
git push origin v1.2.3
```

위 버전은 예시입니다. 태그를 만들기 전에 배포할 변경을 커밋하고 main에 반영하세요. 태그의 커밋에는 `.github/workflows/release.yml`과 배포 도구가 있어야 합니다. 태그는 `vMAJOR.MINOR.PATCH` 형식의 정식 버전만 지원하며 각 숫자는 0~65534, 불필요한 앞자리 0은 허용하지 않습니다. 시험용 접미사나 빌드 메타데이터가 붙은 태그는 거부합니다. 앱과 macOS 번들의 버전은 빌드 서버의 작업 사본에서 태그 번호로 설정하므로 별도의 버전 파일 수정 커밋은 필요하지 않습니다.

세 플랫폼의 빌드·헤드리스 테스트·패키지 검사가 모두 성공해야 릴리스를 준비합니다. 파일 8개의 업로드 크기·SHA-256을 확인한 뒤 초안을 공개하므로 실패 중인 배포는 공개하지 않습니다. 새 Release 워크플로는 앱 실행·실제 화면 캡처·클립보드·전역 키 입력을 수행하지 않습니다. 기존 macOS 브랜치 검증은 별도로 유지합니다.

실패한 실행은 Actions에서 **Re-run failed jobs**로 재시도할 수 있습니다. 미완성 초안은 같은 태그에서 재사용하며 이미 공개된 릴리스는 덮어쓰지 않습니다. **Run workflow**는 선택한 브랜치의 코드로 입력한 버전의 빌드·패키지 검증만 수행하고 새 태그나 릴리스를 만들지 않습니다. 검증 산출물은 `release-files` Artifact에서 14일 동안 받을 수 있습니다. 공개 릴리스 작업에는 저장소의 기본 `GITHUB_TOKEN`을 사용하며 별도 PAT 등록은 필요하지 않습니다. EXE·DMG·설치 ZIP은 CI가 소스에서 생성해 릴리스에 첨부하므로 Git에 추가하지 않습니다.

## 검증 범위

검증 기록은 `docs/verification.md`에 있습니다. Windows 10 22H2 호환성과 실제 혼합 DPI 모니터 조작, 디스플레이 연결 변경, IME 및 클립보드 경합은 추가 현장 검증 대상입니다. 스크롤 캡처, 녹화, OCR, 클라우드 공유는 포함하지 않습니다.
